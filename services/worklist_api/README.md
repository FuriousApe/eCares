# Worklist API

FastAPI REST service exposing the Care Gap Engine's worklist over the Data
Service's gRPC contract (`proto/dataservice.proto`). Swagger/OpenAPI docs
are generated by FastAPI + Pydantic v2 — nothing extra is added to produce
them.

14 endpoints: `GET /health`, `GET /meta`, `GET /patients`,
`GET /patients/{patient_id}`, `GET /tasks`, `GET /tasks/{task_id}`,
`POST /tasks/{task_id}/claim`, `POST /tasks/{task_id}/complete`,
`POST /tasks/{task_id}/decline`, `POST /tasks/{task_id}/snooze`,
`GET /programs`, `POST /admin/sync`, `POST /admin/evaluate`,
`GET /admin/sync-runs`. See the plan (`Care Gap Engine Backend MVP Plan.md`)
for full parameter/behavior details, and `ASSUMPTIONS.md` in this directory
for every decision made beyond what the plan states explicitly.

## Layout

```
services/worklist_api/
  main.py          FastAPI app + `main()` entrypoint (runs via `ROLE=worklist-api`)
  deps.py          role header dependency (X-User-Role / X-User-Id), gRPC stub dependency
  grpc_calls.py    the one place a gRPC failure becomes an AppError (see ASSUMPTIONS.md)
  mapping.py       proto <-> Pydantic conversions, RoleFilter builder
  schemas.py       Pydantic v2 request/response models
  routers/         one file per resource group (health, meta, patients, tasks, programs, admin)
  tests/           pytest + FastAPI TestClient, against a fake in-process gRPC stub
```

## Auth (there isn't any, on purpose)

No real auth in the MVP. Every endpoint except `/health` requires an
`X-User-Role` header (`scheduler` | `clinical` | `admin`); an optional
`X-User-Id` header identifies the caller for audit/assignment purposes. In
Swagger's `/docs` page, click **Authorize** and fill in both header values —
each is registered as its own `APIKeyHeader` security scheme.

## Running it for real

Via Docker Compose (from the repo root, `ecares/`):

```
make up      # builds and starts mysql, redis, kafka, data-service, worklist-api, engine, scheduler, ui
make seed    # loads the CSVs through the sync job
```

Swagger UI: http://localhost:8000/docs
Health check: http://localhost:8000/health

Standalone (needs a running Data Service reachable at `DATA_SERVICE_TARGET`,
default `data-service:50051`):

```
ROLE=worklist-api HTTP_PORT=8000 python -c "from services.worklist_api.main import main; main()"
```

## Running the tests

The test suite mocks the Data Service entirely (a `FakeStub` in
`tests/conftest.py` standing in for the generated `DataServiceStub`) — no
live Data Service, MySQL, Redis or Kafka needed.

From the repo root, with the project's dependencies installed (`fastapi`,
`httpx`, `pydantic`, `pydantic-settings`, `grpcio`, `protobuf`, `pytest` —
already in `pyproject.toml`):

```
python -m pytest services/worklist_api/tests -q
```

Or through Compose, matching the `Makefile`'s `test` target:

```
make test
```

Sanity check that the app is importable without running a server:

```
python -c "from services.worklist_api.main import app"
```
